# aisland — backlog

Open work for this project. Cross-cutting / multi-project initiatives live in the
workspace root `TASKS.md`. Completed items are not archived here — git history is the record.

- [ ] **`aisland backups` has no scheduled sweep** @low @infrastructure — retention is applied by `aisland clean` and by `aisland backups prune`, both of which someone has to run. A machine that stops cleaning keeps its last backups forever. The pieces exist (`prune_store` is a one-line call); what is missing is a place to run it from — a launchd/systemd timer, or a hook in whatever runs `aisland doctor` on this machine.
- [ ] **`aisland source` for a project on a private INDEX:** the `pypi` kind assumes a public index. A project published to a private index would need the source entry to carry (or resolve) that index, which today only reaches uv via the generated root `uv.toml`. (A private *repository* is already covered — use `github`, whose URL comes from `.gitmodules`.) @low @infrastructure
- [ ] **Transitive Gearlux deps of a `pypi`-sourced project** are left to the published wheel's own metadata. That is correct for a leaf like loggair, but a published project that itself depends on an unpublished Gearlux package would fail to resolve — validate this at `aisland source set` time rather than at install time. @low @infrastructure
- [ ] **The scaffolded pre-install ORDER depends on which checkouts exist on the scaffolding machine** @low @maintenance — the topological sort reads each dep's `pyproject.toml` from disk, and a detached submodule (empty dir) contributes no edges, so the same workspace emits `loggair, confluid, liquifai` with checkouts present but alphabetical order with them detached (seen 2026-09-02 as ordering-only churn in four committed pipeline files; since 2026-09-13 only `Jenkinsfile`/`ci.yml` carry the list — `Jenkinsfile.local` installs nothing). Harmless under `--no-deps` (order is cosmetic), but it makes tracked-file content depend on per-machine disk state — derive the ordering edges from a machine-independent source (or drop the sort outright, since every install ignores deps anyway). @low @maintenance
- [ ] **`jenkins scaffold` measures the PARENT package's name for a project that ships inside another package** @low @maintenance — the generated `Jenkinsfile`/`Jenkinsfile.local`/`ci.yml` pass `--cov=<top-level package>`, which for signals-bte is `--cov=signals` and for raidar-ultralytics `--cov=raidar` (regenerated 2026-09-28). Measured on signals-bte: the report lists only that checkout's files — `signals/bte/*` plus the shim `signals/__init__.py`, counted at 0 % because the parent's own `__init__.py` runs instead — so the percentage carries one unrunnable line and the target reads as though the CI measured the parent. Derive the coverage target from the project's `[tool.setuptools.packages.find] include` (the entry that is not the bare parent: `signals.bte`, `raidar.ultralytics`).
- [ ] **Aisland Git Configuration:** Configure `git config pull.rebase false` during project setup in `aisland`. @medium @maintenance
- [ ] **Bumping `CLEARML_SERVER_VERSION` needs a digest refresh, and nothing checks that** @low @maintenance — `services/clearml.py` pins the tag AND `COMPOSE_SHA256`; changing one without the other fails at `aisland clearml start` with a checksum mismatch, which is safe but late. A test cannot fetch (offline CI), so the options are a `--refresh-digest` flag that prints the new value or a doctor check behind a network guard.
- [ ] **Drop `config.py`'s legacy-file fallback** @low @maintenance — `LEGACY_FILES` + the per-key fallback in `load()` exist so a checkout predating the 2026-08-01 merge (`sources.toml` / `frameworks.toml` / `trackers.toml`) does not read as "nothing is configured". Once every machine has run `aisland config migrate` (or any command that writes), the dict and its loop can go, along with `aisland config migrate` itself and the migration call in `setup_workspace`.
- [ ] **Fold `aim._publish_repo` and `clearml._write_env` into `supervisor.write_workspace_env`** @low @maintenance — the shared writer landed with `services/iqengine.py` (2026-08-17); the two older services still carry their own replace-in-place copies of the same loop. Behaviour is identical (key replaced in place, else appended), so this is a pure dedup — keep their tests (`tests/test_aim_service.py::test_publish_repo_*`) as the pins.
- [ ] **`aisland tracker` should offer a "local only" preset** @low @feature — the free self-hostable set (`mlflow`, `tensorboard`, `aim`) is the common choice on a laptop, and spelling all three every time invites a typo. A named preset would also give the docs one command to point at.
- [ ] **`docker-creds` doctor check ignores per-registry `credHelpers`** @low @maintenance — the check covers the measured skew (a dangling top-level `credsStore`), but a `credHelpers` map entry naming a missing helper produces the identical `exec: docker-credential-<x>: executable file not found` on pulls from that one registry. Same read, one more dict walk — extend `doctor.check_docker_credsstore` when it recurs.
