# aisland — backlog

Open work for this project. Cross-cutting / multi-project initiatives live in the
workspace root `TASKS.md`. Completed items are not archived here — git history is the record.

- [ ] **`aisland clean restore <project> [<stamp>]`** @medium @feature — recovery is `cp -R <backup>/files/. <project>/` today, printed by the command itself and good enough that the tool shipped without a verb for it. A real subcommand would let the manifest do the work: list the backups with their sizes and dates, refuse to overwrite a path that came back on its own, and restore a single entry rather than the whole payload. `docs/architecture.md` names this as the natural extension.
- [ ] **`aisland clean` has no way to LIST what is in the store** @low @feature — `clean.read_backups()` already returns every backup with its date and size (the sweep uses it); an `aisland clean --list` / `aisland backups list` would surface it instead of sending the operator to `ls aisland/data/backups`. Decide the command shape together with `restore` above so the two don't end up in different groups.
- [ ] **`aisland source` for a project on a private INDEX:** the `pypi` kind assumes a public index. A project published to a private index would need the source entry to carry (or resolve) that index, which today only reaches uv via the generated root `uv.toml`. (A private *repository* is already covered — use `github`, whose URL comes from `.gitmodules`.) @low @infrastructure
- [ ] **Transitive Gearlux deps of a `pypi`-sourced project** are left to the published wheel's own metadata. That is correct for a leaf like loggair, but a published project that itself depends on an unpublished Gearlux package would fail to resolve — validate this at `aisland source set` time rather than at install time. @low @infrastructure
- [ ] **A project's own name appears in its `Jenkinsfile.local` internal-dep list.** `annotaide` and `signals` declare each other in their `[dev]` extras, so the transitive closure `discover_gearlux_projects` walks loops back to the project being scaffolded and emits a `--no-deps -e <self>` line before `.[dev]`. Harmless (a duplicate editable install) but confusing to read — exclude the scaffolded project from its own dep list. Pre-existing; unrelated to the guard fix. @low @maintenance
- [ ] **Aisland Git Configuration:** Configure `git config pull.rebase false` during project setup in `aisland`. @medium @maintenance
- [ ] **Bumping `CLEARML_SERVER_VERSION` needs a digest refresh, and nothing checks that** @low @maintenance — `services/clearml.py` pins the tag AND `COMPOSE_SHA256`; changing one without the other fails at `aisland clearml start` with a checksum mismatch, which is safe but late. A test cannot fetch (offline CI), so the options are a `--refresh-digest` flag that prints the new value or a doctor check behind a network guard.
- [ ] **Drop `config.py`'s legacy-file fallback** @low @maintenance — `LEGACY_FILES` + the per-key fallback in `load()` exist so a checkout predating the 2026-08-01 merge (`sources.toml` / `frameworks.toml` / `trackers.toml`) does not read as "nothing is configured". Once every machine has run `aisland config migrate` (or any command that writes), the dict and its loop can go, along with `aisland config migrate` itself and the migration call in `setup_workspace`.
- [ ] **`aisland tracker` should offer a "local only" preset** @low @feature — the free self-hostable set (`mlflow`, `tensorboard`, `aim`) is the common choice on a laptop, and spelling all three every time invites a typo. A named preset would also give the docs one command to point at.
