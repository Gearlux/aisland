# Aisland Mandates

- **Workspace-Relative Path Resolution:** All service binaries, data directories, and logs MUST resolve to the `aisland/` directory inside the current workspace root — discovered dynamically (e.g., by walking up from the invocation `cwd` to find `TASKS.md` or `.git`), never hardcoded to an absolute path like `~/source/aisland/`. The workspace root is derived from the `cwd` at invocation; the target directory is always `<workspace_root>/aisland/`, regardless of the subdirectory the `aisland` command is run from. Never pollute the workspace root itself with service state.
- **PID-Based Lifecycle:** Process tracking MUST use PID files with `pgrep` pattern fallback. Never assume a service is stopped just because the PID file is missing.
- **Cross-Platform:** Process management (start, stop, signal handling) MUST work on macOS, Linux, and Windows. Use `SIGTERM` on Unix, `taskkill` on Windows.
- **Service Isolation:** Each service (Jenkins, MLflow) MUST have its own data directory, log file, and PID file. Never share state between services.
- **BaseService Contract:** All new services MUST extend `BaseService` and implement `start()`, `stop()`, `status()`, and `reset()`.
- **Job Seeding:** Jenkins `init` MUST auto-create multi-branch pipeline jobs for all workspace projects using config.xml templates.
- **Generated Workspace Files Are Portable + Gitignored:** Files `aisland setup` writes to the workspace root (`pyrightconfig.json` via `manager._write_pyrightconfig`, the `project.bashrc` symlink, `.project.bashrc.completion`, `.gemini/settings.json` via `manager._write_gemini_settings`, and the root `uv.toml` via `manager._write_root_uv_toml`) are generated artifacts: gitignore them and regenerate on every setup so the tree never goes dirty and the output always tracks the live project set (discovered via `get_install_order` / `discover_projects` / `_discover_mcp_servers`, not a hand-maintained list). Prefer workspace-relative paths (e.g. pyrightconfig's `venvPath: "."`) — never bake in an absolute like `/Users/<name>/acme`. **Exception:** `.gemini/settings.json` MUST use ABSOLUTE venv paths because the MCP client (Gemini CLI) launches each server as a subprocess from an arbitrary cwd; that machine-specific absolute is precisely why the file is gitignored + regenerated per machine rather than committed. Don't "portability-fix" it to relative paths — that breaks the launcher.
- **Root `uv.toml` Is Generated From The Activated Set (Never Committed With A Private Index):** The root `uv.toml` is built by `manager._write_root_uv_toml` = a workspace base (`_ROOT_UV_BASE`, e.g. `override-dependencies`) **merged** with each ACTIVATED project's own `uv.toml` (union list keys like `extra-index-url` with dedup, last-wins scalars; hand-emitted via `_emit_uv_toml` with an AUTO-GENERATED provenance header). A private index (Company Artifactory) lives in the owning project's `uv.toml` (e.g. `vendorcli/uv.toml`) and reaches the root file ONLY when that project is activated. This is why the root `uv.toml` MUST stay gitignored and regenerated per machine: a non-corporate machine that does not activate vendorcli/bridge never gets the (unreachable) index, so `uv pip install` from the root never tries to contact it. NEVER commit a root `uv.toml` carrying a private `extra-index-url`, and NEVER move a private index back into the root base — it belongs in the project's `uv.toml`.
- **Submodule Activation Is Per-Machine + Prompt-Driven:** `aisland setup` resolves *optional* submodules (`manager._project_is_optional` → ships its own `uv.toml` OR is `active = false` in `.gitmodules`; ordinary projects auto-activate and are never prompted) and records the answer per-machine in `.git/config` (`submodule.<name>.active`, via `_set_local_submodule_active`) — NEVER in committed `.gitmodules` (that file's `active` flag is the shared default only). Semantics (`_resolve_submodule_activation`): a decided module (a value already in `.git/config`) is honored silently; an undecided/NEW optional module is **prompted even under `--non-interactive/-y`** (a machine must consciously opt into a private/corporate project before it tries to use its index or clone its remote); `--activate <name>` / `--deactivate <name>` set the decision without prompting. `reconcile_submodules` then aligns the working tree with `committed_active if local is None else local`, so a per-machine deactivate deinits a committed-active submodule. Keep the deinit protective (no `-f`) unless the user asks otherwise.
